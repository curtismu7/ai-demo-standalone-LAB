# ai-demo-standalone

Demo-tier standalone app (catalog D128, port 7810): a mock of the AI-DEMO2 dashboard. The 87-use-case catalog (8 tracks) runs against ONE mock PDP: token, then gateway chain check, then policy (directory groups read on EVERY decision, tier ceilings Standard $2000 / Premium $50000, premium-only tools), then the obligation layer. Stage 2 is shipped: foundations, controls, HITL (UC7/UC8/UC22: confirm $250, step-up $500, approval tools, CIBA, call-bound receipts) and the A2A hand-off (UC2/2.5/2.6/2.7) are wired in-process (11 scenario chips plus an A2A panel). Attacks, learn, tools, nhi and demo are catalog entries only. Real is reserved (the toggle works, there is no live data path). Direction: it becomes a look-alike of AI-DEMO2's `/dashboard` Customer dashboard (account cards, Banking assistant chat, token-chain panel); design mocks live in AI-DEMO2 `demo_api_ui/design/` (read only).

- Run: `./scripts/run.sh` (http://localhost:7810). Test: `npm ci && npm test && npm run build` (server is `node --test test/*.test.js`, a glob; web is vitest; root `scripts/*.test.mjs`). Preflight: `npm run doctor`. Reset: `npm run reset`. Real counts (after the receipt fixes, 2026-11-10): 65 server + 25 web + 19 packaging.
- Core: `server/src/pdp.js` (pure `validateToken`, `validateChain`, `evaluatePolicy`, `decide`, `decideWithObligation`, `exchange`, injected clock). `hitl.js`: `evaluateObligation` (BANDS confirm 250 / stepUp 500, no deny band: the tier ceilings are the hard limits; HITL tools `create_transfer` `create_wire_transfer` `approve_large_transfer`, CIBA tool `move_money`), `createChallenge`, `verifyAnswer` (mock OTP 123123; reports `mfaVerified`), `mintReceipt` (`MfaVerified` only when told an MFA answer was verified), `receiptValid` (binding check), `createReceipts` (the per-workspace store: pending challenges, answered ids, issued receipts; bounded 200 each, 5-minute TTL; `redeem` looks a receipt up and consumes it), `answerChallenge` (store lookup, verify, spend, issue). `a2a.js`: `exchangeOne`, `exchangeTwo` (scope narrowed), `evaluateA2a` (registry check), `createRegistry`, `agentCard`. Data: `pdpData.js` (seeded directory, limits), `policyData.js` (banner, intro, facts, the 11 scenarios, talk track, `{{castBrand}}`-style tokens filled by `cast.js`, 3 vertical packs; a test fails on an undefined token). Teaching layer: `explain.js` (per-stage narrative, lesson, product roles, mock hops with `traceparent`). Catalog: `server/data/catalog.json` (`ai-demo-catalog/1`, extracted from AI-DEMO2 `useCases.js`). Diagram: `server/diagrams/decision-chain.json` (diagram-studio/1).
- API (`app.js`): `GET /api/health` (demo-health/1), `GET /api/info`, `POST /api/mode` (rule 19: exactly `{ source: "mock"|"real" }`, 409 when Real unconfigured), `GET /api/scenarios?vertical=`, `GET /api/catalog?track=`, `GET /api/diagram?name=`, `GET|POST /api/directory[/set]`, `POST /api/consent`, `POST /api/authorize` (200 PERMIT, 202 OBLIGATION, 403 DENY, 401 no bearer; optional `receipt`), `POST /api/challenge`, `POST /api/challenge/answer`, `GET /api/a2a/agent-card`, `POST /api/a2a/exchange/one|two`, `POST /api/a2a/tool`, `GET /api/a2a/registry`, `POST /api/a2a/registry/set`, `GET /api/runs`, `POST /api/reset`; `GET /shelf` (mounted at `/shelf`, not `/api/shelf`: the header Shelf link 404s, known gap). Workspace id in `X-Workspace` (`^[a-z0-9-]{1,40}$`, default `default`); per-workspace state is directory, runs, challenges and receipts (the store above), specialist registry.
- Decision contract (do not weaken): stages run in order token -> gateway -> policy -> obligation and the first refusal wins; a missing bearer is a 401 before anything; the actor must be on the allow-list; an upstream audience is never accepted; the group gate applies to every tool call regardless of scopes; premium-only tools need `premiumTier`; amounts are tier bands, not tool arguments; an obligation is a pause (202), never a denial; a receipt must be one this server issued in this workspace, unspent, unexpired, and bind user + tool + obligation + amount (a missing amount only matches a missing amount); it is consumed by the call it permits and a refused attempt does not burn it; a refused receipt leaves the call a 202 OBLIGATION with `receiptCheck` naming why; a challenge is answered against the server's stored copy (never the caller's) and answers once; `MfaVerified` is true only on a STEP_UP receipt; there is no deny band above the tier ceilings; A2A needs a nested act chain (depth >= 2) and a REGISTERED specialist.
- Known gaps in the stage-2 code (documented, not fixed): receipts are a teaching mechanism, not a security boundary (unsigned, id is the credential, the workspace id is not authenticated, memory only; `/api/challenge` does not run the policy); page text (INTRO, the "stages" fact, the catalog hint, "stage 2-4" in the use-case detail, and the web test that pins it) still says HITL lands later.
- Rules that bite: loopback bind only; same-origin writes; zero outbound network (netguard); only `.example`/`.invalid` hosts; exactly ONE port, 7810 (`safety.js` `PORT_MIN = PORT_MAX = DEFAULT_PORT`; 7710 belongs to diagram-prove-lab); every token, challenge, receipt and the OTP shown raw and labelled mock; `POST /api/mode` is exactly `{ source: "mock"|"real" }`; do not hand-edit `docs/talk-track.md` (generated by `npm run talk-track`) or `content-pack.json` (generated by `npm run content-pack`; a test fails on drift).
- Web: `web/src/App.jsx` (tabs, presenter, Reset, Mock/Real toggle, `X-Workspace` via `workspace.js`), `components/PolicyGate` (scenario chips, Decision panel, `ObligationPanel` consent/MFA/CIBA -> receipt -> re-run, `A2aPanel`, Tech proof hops, Live directory board, catalog list, use-case detail), `DiagramTab` + `PatternDiagram`, `return-link/` (vendored byte for byte, hash-pinned: do not edit). Colours come from `tokens.css` only. The page is replaced by the Customer-dashboard rebuild.
